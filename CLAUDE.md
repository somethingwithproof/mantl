# Mantl

## Purpose

Mantl is a Kubernetes-native platform with Compliance-as-Code as its differentiator.
It is a 2026 successor in spirit to the original Cisco Mantl microservices platform,
rebuilt on GitOps (ArgoCD), Terraform/OpenTofu, and a Go compliance operator. The
operator turns compliance frameworks (SOC2, HIPAA, PCI-DSS, CIS Kubernetes) into
reconciled cluster state: profiles select controls, controls map to admission and
runtime policies, violations surface as `Finding` custom resources, and audits
capture hashed, immutable evidence.

This is a Go project. An earlier `CLAUDE.md` described it as Python; that was wrong.
Go is the operator and CLI language. Python remains only in auxiliary tooling and is
not the system under development here.

## Architecture

Three ownership boundaries. Keep them clean.

| Layer | Owns | Lives in |
|-------|------|----------|
| CRDs + controllers | Kubernetes API types and reconcile loops. Desired state, status, finalizers, requeue logic. | `apis/`, `controllers/` |
| Package logic | Pure Go that the controllers and CLI call. Spec parsing, rendering, evidence capture, bootstrap ordering. No Kubernetes reconcile concerns. | `pkg/` |
| Frameworks-as-data | Compliance content. Control catalogs, profiles, policy mappings expressed as YAML, not code. | `compliance/frameworks/`, `policies/kyverno/` |

Rules that hold the boundaries:

- Controllers translate between the cluster and `pkg/` logic. They do not embed
  framework content or business rules that belong in `pkg/`.
- `pkg/` does not import controller-runtime reconcile machinery. It takes and
  returns plain Go values so it can be tested without a cluster.
- A framework is data. Adding or changing a control is a YAML change under
  `compliance/frameworks/`, not a Go change, unless the control needs a new
  evidence collector or policy primitive.
- `platform/` is vendored third-party Helm charts (Loki, Falco, and others). It is
  not Mantl code. Do not refactor it, do not add `go.mod` files to it, and do not
  treat its failures as Mantl bugs (see ADR 004).

## Module layout

```
apis/
  compliance/v1alpha1/   # ComplianceProfile, Finding, ComplianceAudit types + kubebuilder markers
  platform/v1alpha1/     # platform CRD types
  */zz_generated.deepcopy.go  # generated by controller-gen, do not hand-edit
controllers/
  compliance/            # profile, finding, audit reconcilers (+ tests)
pkg/
  compiler/              # spec parser, terraform renderer, gitops renderer
  bootstrap/             # bootstrap DAG ordering
  evidence/              # resource snapshot capture
cmd/
  mantl/                 # mantl CLI
  compliance-operator/   # operator entrypoint
compliance/
  frameworks/            # soc2, hipaa, pci-dss, cis-kubernetes (framework + profile YAML)
  operator/              # operator deployment, CRD manifests, metrics
  evidence/, reports/, dashboards/, cli/, api/
policies/
  kyverno/               # admission policies (image signing, registry restriction, labels)
infra/
  terraform/blueprints/  # aws-eks (GA), gcp-gke, azure-aks; do-doks/linode-lke/oci-oke/ibm-iks experimental
  terraform/modules/
charts/
  mantl-platform/        # helm chart
platform/                # VENDORED upstream charts, not our code
docs/
  adr/                   # architecture decision records
  superpowers/specs/     # roadmap and design specs
```

Cloud parity is three clouds (AWS, GCP, Azure) at a common hardening baseline. The
rest are labeled experimental and carry no CI or parity guarantee (ADR 005).

## Implementation rules (Go)

- Logging is `log/slog` only. No `fmt.Printf` for logging, no `log` standard
  package. Use stable structured keys; never log secrets or raw evidence payloads.
- Wrap errors with context: `fmt.Errorf("capture %s/%s: %w", kind, name, err)`.
  Preserve the chain with `%w` so callers can match with `errors.Is`/`errors.As`.
- CRD types carry kubebuilder markers in `apis/*/v1alpha1/types.go`. After changing
  a type, regenerate `zz_generated.deepcopy.go` with `controller-gen`
  (`controller-gen object paths=./apis/...`) and regenerate CRD manifests for any
  schema change. Do not hand-edit generated files.
- Never commit compiled binaries. The CLI and operator build to local paths that
  belong in `.gitignore`, not in version control.
- Terraform providers are pinned. Every blueprint and module pins provider versions;
  do not float them.
- Kyverno policies referenced by a framework MUST exist in `policies/kyverno/`. A
  control that maps to a missing policy is a broken framework. If you add a control
  that names a policy, add the policy in the same change.
- Evidence storage follows ADR 003: `Finding` and audit CRDs hold metadata and a
  URI pointer; raw payloads go to versioned, WORM object storage, never into etcd.

## Testing

- The canonical command is `make go-test`, not `go test ./...`. `make go-test`
  excludes the vendored `platform/` packages whose upstream tests would otherwise
  turn CI red for code Mantl does not own (ADR 004). Running `go test ./...`
  directly will fail on vendored chart tests.
- Controller behavior is tested in `controllers/compliance/*_test.go`. Keep
  reconcile logic testable by pushing pure logic into `pkg/`.
- No test may depend on a live cluster or a working `kubectl`. The evidence package
  separates argument validation from process execution precisely so the rules can be
  exercised without a cluster (`pkg/evidence/snapshot_test.go`). When a code path
  shells out to `kubectl`, test the validation and the error path, not a live call.
- Test the error and boundary paths, not only the happy path. Reconcilers must be
  covered for requeue, not-found, and status-update failures.

## ADR discipline

Architecture decisions go in `docs/adr/` as numbered records (current: 003 evidence
storage, 004 test scope, 005 cloud parity). Before a change that alters a boundary,
a storage contract, a test-scope rule, or a supported-cloud claim, write or update
an ADR. The roadmap and larger designs live in `docs/superpowers/specs/`. Do not
make a boundary-changing decision implicitly in a code PR; record it.

## Security

These areas are sensitive and require review before merge:

- Compliance logic and framework content. A wrong control mapping or a dropped
  policy reference silently weakens the audit posture.
- IAM and cloud credentials. The operator needs scoped roles (for example IRSA) to
  write evidence. Grant least privilege; do not widen a role to make a test pass.
- Supply chain. The release path signs artifacts with Cosign (keyless OIDC) and
  generates SLSA Level 3 provenance and SBOMs (`.github/workflows/release.yml`,
  `.github/workflows/slsa-provenance.yml`). Changes to signing, provenance, or
  workflow permissions are security changes.

Report vulnerabilities through GitHub Security Advisories, not public issues. See
`SECURITY.md`.

## What NOT to do

- Do not run `go test ./...` directly. Use `make go-test`.
- Do not add features to the README that are not implemented. README claims must map
  to working code or carry an honest maturity label (GA / beta / experimental).
- Do not drop `go.mod` files into vendored charts under `platform/`. Chart updates
  overwrite them, and the test scope already excludes that tree (ADR 004).
- Do not commit compiled binaries.
- Do not hand-edit `zz_generated.deepcopy.go`; regenerate with controller-gen.
- Do not store raw compliance evidence in etcd or in CRD bodies (ADR 003).
- Do not float Terraform provider versions.
- Do not refactor or "fix" vendored `platform/` charts; they are upstream code.
